# Travel Buddy — TripMate (Live Location, PostgreSQL + Auth)

### 🆕 ดีไซน์ใหม่ "Travel Buddy" (รอบนี้)
เปลี่ยนหน้าตาทั้งหมดเป็นดีไซน์ระบบ **Travel Buddy** (สไตล์ editorial/magazine, Electric Blue + Lime Glow, ฟอนต์ Plus Jakarta Sans, การ์ดโค้งมนขนาดใหญ่) โดยใช้ Tailwind CDN + token ชุดสีตาม `travel_buddy_project_brief.md` ที่ให้มา — **backend/DB ยังเป็นระบบเดิมทั้งหมด ไม่มีอะไรเปลี่ยน** แค่หน้าตาฝั่ง frontend (`public/index.html`, `public/app.js`) ที่เขียนใหม่ให้ต่อกับ API เดิมได้ตรงๆ

โครงสร้างหน้าจอใหม่:
- **หน้า Auth**: เข้าสู่ระบบ/สมัครสมาชิก สไตล์การ์ดเรียบหรู ปุ่ม pill
- **My Trips**: ทริปที่กำลังไปเด่นเป็นการ์ดใหญ่แบบ magazine (มีรูปปก, badge "Live"), ทริปอื่นๆ เป็นการ์ดรอง, ทริปที่ปิดแล้วเป็นลิสต์กะทัดรัด, ปุ่ม + ลอย (FAB) เปิด bottom sheet สร้าง/เข้าร่วมทริป
- **หน้าทริป**: แผนที่ Leaflet จริงพร้อม floating pill แสดงจำนวนสมาชิก + สวิตช์ Sharing/Hidden, แท็บล่าง Map / Schedule / Expenses / Members (Schedule กับ Expenses ยังเป็นหน้า "เร็วๆ นี้" เพราะยังไม่มี backend รองรับ)

รูปปกทริปใช้ภาพจาก Unsplash แบบสุ่มตาม hash ของรหัสทริป (ไม่ใช่รูปจริงของทริป เพราะยังไม่มีฟีเจอร์อัปโหลดรูป)

### 🆕 Phase 1: Schedule + Expenses (รอบนี้)
Travel Buddy แบ่งเป็นหลาย Phase ตามโมดูล — Phase นี้เพิ่ม 2 ฟีเจอร์ที่ทำงานได้จริงในหน้าทริป (แทนที่หน้า "เร็วๆ นี้" เดิม):

**กำหนดการเดินทาง (Schedule)**
- เพิ่ม/ลบกิจกรรมในทริป พร้อมหมวดหมู่ (สถานที่/อาหาร/เดินทาง/ที่พัก/กิจกรรม/อื่นๆ), สถานที่, วันเวลา, รายละเอียด
- แสดงเป็นไทม์ไลน์เรียงตามเวลา อัปเดตเรียลไทม์ให้ทุกคนในทริปผ่าน Socket.IO (event `itinerary-updated`)
- ตาราง `itinerary_items`

**ค่าใช้จ่ายร่วมกัน (Expenses)**
- เพิ่มค่าใช้จ่าย ระบุคนจ่าย (ผู้ใช้ปัจจุบันเสมอ) และหมวดหมู่
- **หารเท่ากันอัตโนมัติ** ระหว่างสมาชิกทุกคนในทริป ณ ตอนคำนวณ (ไม่ผูก split ล่วงหน้า เพื่อรองรับสมาชิกเข้า-ออกทริปได้)
- การ์ด "ใครติดเงินใคร" คำนวณยอดสุทธิ (net) ต่อคนแบบเรียลไทม์
- ตั้งงบประมาณทริป (ไม่บังคับ) มี progress bar เตือนเมื่อใช้เกินงบ (เปลี่ยนสีเป็นแดง)
- ตาราง `expenses` + คอลัมน์ `trips.budget`
- อัปเดตเรียลไทม์ผ่าน Socket.IO (event `expenses-updated`)

ทั้งสองฟีเจอร์ผูกกับ permission เดิม (ต้องเป็นสมาชิกทริปนั้นเท่านั้นถึงจะเพิ่ม/ลบ/ดูได้)

### 🆕 Phase 2: Explore + Community Trips + UI ปรับปรุง (รอบนี้)

**UI ที่ปรับปรุง**
- เพิ่ม **bottom nav ระดับแอป** (Explore / Trips / Profile) ที่หน้ารวมทริป — ของเดิมไม่มี nav ตรงนี้เลย ทำให้ดูขาดๆ ตอนนี้ตรงตามดีไซน์ต้นฉบับมากขึ้น
- เพิ่มหน้า **Profile** เรียบง่าย (อวตารตัวอักษรย่อชื่อ, ปุ่มออกจากระบบย้ายมาไว้ที่นี่แทน header)
- Empty state มีไอคอน + คำอธิบายแทนข้อความเปล่าๆ, live badge มี animation pulse

**Explore + Community Trips**
- เปิดทริปให้เป็น **สาธารณะ** ได้จากแท็บ Members ในหน้าทริป (สวิตช์ + ใส่จุดหมาย/คำอธิบาย)
- หน้า **Explore** แสดงทริปสาธารณะทั้งหมด (ไม่รวมทริปที่ตัวเองเข้าร่วมแล้ว) เรียงตามจำนวนสมาชิก การ์ดแรกเป็น hero ใหญ่ ที่เหลือเป็นการ์ดแนวนอน
- กดปุ่ม "เข้าร่วม" ใน Explore เข้าทริปได้ทันที (ใช้ระบบรหัสทริปเดิม เพราะทริปสาธารณะไม่ต้องปิดรหัสอยู่แล้ว)
- ตาราง: `trips.visibility` (public/private), `trips.destination`, `trips.description`

⚠️ **บั๊กที่เจอและแก้ระหว่างทดสอบ**: endpoint `/api/community/trips` ตอนแรกไม่ได้ผูกกับ `requireAuth` middleware (เพราะ path ไม่ตรงกับ `/api/trips` ที่ตั้ง middleware แบบ prefix ไว้) ทำให้เรียกได้โดยไม่ล็อกอิน และ filter คนที่เข้าร่วมแล้วออกไม่ทำงานเพราะ `req.userId` เป็น `undefined` — แก้โดยเพิ่ม `app.use("/api/community", requireAuth)` แล้วทดสอบยืนยันด้วย curl ซ้ำจนถูกต้อง

### 🆕 Phase 3: Travel Stories (รอบนี้)
ฟีดเรื่องเล่าทริปแบบเต็มจอ scroll ทีละการ์ด (คล้าย Stories/Reels) ตามดีไซน์ต้นฉบับ:

- **โพสต์เรื่องเล่า**: ใส่ลิงก์รูปภาพ (ยังไม่มีระบบอัปโหลดไฟล์ในโปรเจกต์นี้ จึงรับเป็น URL รูปที่ผ่าน validation http/https เท่านั้น), แคปชั่น, แท็ก (สูงสุด 6 แท็ก), เลือกผูกกับทริปของตัวเองได้ (ไม่บังคับ)
- **ไลค์**: กดหัวใจ toggle เปิด/ปิดได้ นับจำนวนจริงจาก DB ไม่ใช่ตัวเลขปลอม
- **คอมเมนต์**: เปิด sheet ด้านล่างดู/เพิ่มคอมเมนต์ได้แบบเรียลไทม์ (โหลดใหม่ทุกครั้งที่เปิด)
- **แชร์**: ใช้ Web Share API ของเบราว์เซอร์ถ้ามี ไม่มีก็ copy ลิงก์+แคปชั่นไปคลิปบอร์ดแทน
- **ลบเรื่องเล่า**: ลบได้เฉพาะเจ้าของเท่านั้น (ตรวจสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่มฝั่งหน้าเว็บ)
- เพิ่มแท็บ **Stories** เข้าไปใน bottom nav ระดับแอป (ตอนนี้มีครบ Explore / Trips / Stories / Profile ตามดีไซน์ต้นฉบับแล้ว)
- ตาราง: `stories`, `story_likes`, `story_comments`

ทดสอบผ่าน API จริงครบ: สร้าง/ลบ story (เฉพาะเจ้าของ), validate URL, ไลค์/เลิกไลค์, คอมเมนต์, และตรวจสิทธิ์การเข้าถึงทุก endpoint (401 เมื่อไม่ล็อกอิน)

### 🆕 Phase 4: Profile + Find Travelers (รอบนี้ — ครบ 4 Phase แล้ว)

**Profile**
- แก้ไข bio, ที่อยู่, ความสนใจ (แท็ก) ได้จริง บันทึกลง DB
- สถิติจริงจากข้อมูลที่มีอยู่แล้ว ไม่ปลอม: จำนวนทริปที่เข้าร่วม (`Trips`), จำนวนจุดหมายที่ไปมา นับจาก `trips.destination` ที่ไม่ซ้ำ (`Places`), จำนวนเรื่องเล่าที่โพสต์ (`Stories`)
- สวิตช์ **"เปิดให้ค้นหาเจอ"** (discoverable) — ปิดเป็นค่าเริ่มต้นเพื่อความเป็นส่วนตัว ผู้ใช้ต้องกดเปิดเองถึงจะไปโผล่ในหน้า Find Travelers

**Find Travelers** (อยู่ในแท็บ Explore > นักเดินทาง ตามดีไซน์ต้นฉบับที่ทั้งสองหน้าใช้ไอคอน Explore เดียวกัน)
- ค้นหานักเดินทางที่เปิด discoverable จากชื่อ/ที่อยู่/ความสนใจ
- คำนวณ **% match** จริงจากจำนวนความสนใจที่ตรงกันระหว่างเรากับเขา (ไม่ใช่ตัวเลขสุ่ม) — ถ้าเรายังไม่ตั้งความสนใจของตัวเอง จะไม่โชว์ % (เพราะคำนวณไม่ได้อย่างมีความหมาย)
- ปุ่ม **"ชวนไปทริป"**: เลือกทริปของตัวเอง (เฉพาะทริปที่เปิดอยู่) แล้วส่ง**คำเชิญ** ไม่ใช่เพิ่มเข้าทริปทันที เพื่อความยินยอมของอีกฝ่าย

**ระบบคำเชิญเข้าทริป (Trip Invites)**
- คำเชิญที่รอตอบรับแสดงเป็นการ์ดด้านบนสุดของหน้า "My Trips" พร้อมปุ่มตอบรับ/ปฏิเสธ
- ตอบรับแล้วถึงจะถูกเพิ่มเป็นสมาชิกทริปจริง (ผ่านฟังก์ชัน `addMember` เดิม ใช้ path เดียวกับการ join ด้วยรหัส)
- เชิญคนที่อยู่ในทริปแล้วไม่ได้ (กันซ้ำ), เชิญตัวเองไม่ได้, เชิญซ้ำหลังถูกปฏิเสธได้ (สร้างคำเชิญใหม่ทับของเดิม)
- ตาราง: `trip_invites` (unique ต่อ trip+ผู้ถูกเชิญ กันคำเชิญค้างซ้ำซ้อน)

ทดสอบผ่าน API จริงครบ 2 บัญชี: ตั้ง profile + interests ต่างกัน → คำนวณ match% ถูกต้อง (33% จาก 1 ใน 3 ความสนใจตรงกัน) → เชิญเข้าทริป → ผู้ถูกเชิญเห็นคำเชิญ → ตอบรับ → ยืนยันเป็นสมาชิกจริงใน `/api/whoami`

### 🆕 Phase 5: Route + Distance + Location Alert + Trip Host + Join via Link (รอบนี้)

**Trip Host (หัวหน้าทริป)** — เพิ่ม role แรกของระบบ ตั้งชื่อ `host` ไม่ใช้คำว่า `owner` เพื่อไม่ชนกับ role เจ้าของเว็บไซต์ในอนาคต ผู้สร้างทริปกลายเป็นหัวหน้าทริปอัตโนมัติ มีสิทธิ์พิเศษเฉพาะ: แก้ชื่อ/วันที่ทริป, อัปโหลดรูปปก, ลบทริปถาวร (คนอื่นทำ 3 อย่างนี้ไม่ได้ โดน 403)

**Trip fields ที่เพิ่ม**
- วันเริ่มต้น/สิ้นสุดทริป (`start_date`/`end_date`)
- แก้ไขชื่อทริปได้ (เดิมทำไม่ได้เลย)
- **ลบทริปถาวรได้** — แต่บังคับให้ "ปิดทริป" ก่อนเสมอ กันลบทริปที่ยังใช้งานอยู่โดยไม่ตั้งใจ (ไม่มี undo)
- **รูปปกอัปโหลดจริง** ผ่าน `multer` เก็บไฟล์ไว้บนเครื่อง server เอง (`public/uploads/covers/`) ไม่ใช่รูปสุ่มจาก Unsplash แบบเดิมอีกต่อไป (จำกัด JPEG/PNG/WEBP ไม่เกิน 5MB)

**Route (เส้นทาง A→B→C→D)**
- แก้ปัญหาเดิมที่ `itinerary_items.lat/lng` มีในตารางแต่ไม่เคยถูกใช้ — ตอนนี้เพิ่มกิจกรรมพร้อมปักพิกัดได้จริงผ่าน mini-map picker (แตะปักหมุด) หรือปุ่ม "ใช้ตำแหน่งปัจจุบัน"
- แผนที่หลักพล็อตเส้นทางเป็นเส้นประเชื่อมจุดตามลำดับ พร้อมเลขกำกับ 1,2,3... มีปุ่มเปิด/ปิดการแสดงเส้นทาง
- ผู้ใช้เป็นคนกำหนดลำดับเอง (ไม่มี AI จัดลำดับอัตโนมัติ ตามที่กำหนดไว้)

**Distance (ระยะห่าง)**
- สมาชิก↔สมาชิก: แสดงในแท็บ Members "250 ม. จากคุณ"
- สมาชิก↔สถานที่: แสดงในแท็บ Schedule ต่อท้ายชื่อสถานที่
- สมาชิก↔จุดนัดหมาย: ใช้คำนวณ Location Alert (ด้านล่าง)
- คำนวณด้วยสูตร Haversine จริง (ระยะทางตรงบนพื้นโลก ไม่ใช่ระยะทางถนน)

**Location Alert** (in-app banner บนแผนที่ ไม่ใช่ push notification — ไม่มีการอ้างว่าตรวจจับอุบัติเหตุได้)
- ห่างจากศูนย์กลางกลุ่มเกิน 500 ม.
- ห่างจากจุดนัดหมายเกิน 500 ม.
- ไม่มีการเคลื่อนที่เกิน 20 นาที (ตรวจจริงจาก DB โดยเทียบพิกัดเก่า-ใหม่ ไม่ใช่แค่เวลาที่ ping เข้ามา — คอลัมน์ใหม่ `members.last_moved_at`)
- ใกล้ถึงกำหนดการ (แจ้งล่วงหน้า 15 นาที)
- แสดงพร้อมกันได้สูงสุด 3 การ์ด เรียงตามความสำคัญ

**Join via Link**
- ลิงก์รูปแบบ `/join/RHASCODE` เปิดแล้วเข้าร่วมทริปทันทีหลังล็อกอิน/สมัครสมาชิก (ถ้ายังไม่ล็อกอิน ระบบพาไปหน้า login ก่อนแล้วเข้าร่วมต่ออัตโนมัติ)
- ปุ่ม "คัดลอกลิงก์เชิญเพื่อน" ในแท็บ Members

ทดสอบผ่าน API จริงครบ: host-only 403 กันสิทธิ์ถูกต้อง, validate วันที่ (สิ้นสุดก่อนเริ่มต้องพัง), ลบทริปที่ยังเปิดอยู่ต้องพัง, ลบสำเร็จหลังปิดทริป, อัปโหลดไฟล์รูปจริงและเช็คไฟล์ถูกสร้างบน disk จริง, itinerary มี lat/lng ครบ, meetup point บันทึกถูกต้อง

## วิธีรันโปรเจกต์

1. ติดตั้ง dependencies:
   ```
   npm install
   ```
2. ตั้งค่าฐานข้อมูล — คัดลอก `.env.example` (หรือแก้ `.env` ที่มีอยู่) แล้วใส่ connection string ของ PostgreSQL จริง:
   ```
   DATABASE_URL=postgres://user:password@localhost:5432/tripmate
   ```
   ต้องสร้างฐานข้อมูลชื่อ `tripmate` (หรือชื่อที่ตั้งใน URL) ไว้ล่วงหน้าด้วย `createdb tripmate` — ตารางข้างในจะถูกสร้างอัตโนมัติจาก `db/schema.sql` ตอนสตาร์ทเซิร์ฟเวอร์ครั้งแรก (ปลอดภัยที่จะรันซ้ำ)
3. รันเซิร์ฟเวอร์:
   ```
   node server.js
   ```
   ถ้าเชื่อมต่อสำเร็จจะเห็น `[db] Connected to PostgreSQL and schema is ready.` ถ้าไม่ตั้ง `DATABASE_URL` แอปจะยังเปิดหน้าเว็บได้ แต่ฟีเจอร์สร้าง/เข้าร่วมทริปจะใช้งานไม่ได้ (มี warning เตือนใน console)
4. เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`
   - เปิดหลายแท็บ/หลายเครื่อง (ในวง LAN เดียวกัน) เพื่อจำลองสมาชิกหลายคน
   - อนุญาตการเข้าถึงตำแหน่ง (Location) เมื่อเบราว์เซอร์ถาม

## สิ่งที่ปรับปรุงจากเดิม

- **แถบสมาชิก (Sidebar)**: เห็นรายชื่อ สี และเวลาที่อัปเดตตำแหน่งล่าสุดของแต่ละคน
- **Marker สีต่างกันต่อคน** + popup แสดงชื่อ
- **ปุ่ม "ไปยังตำแหน่งของฉัน"** (🎯) และปุ่มซูมแผนที่
- **โค้ดฝั่งเซิร์ฟเวอร์แข็งแรงขึ้น**: จัดการ join/disconnect สะอาดขึ้น ป้องกันชื่อว่าง/ยาวเกิน
- **Responsive**: ใช้งานได้บนมือถือ

### 🆕 ระบบสมัครสมาชิก / เข้าสู่ระบบจริง (Auth)
- **สมัครสมาชิกด้วย username + password** รหัสผ่านเก็บแบบ **bcrypt hash** เท่านั้น ไม่เก็บ plain text เด็ดขาด
- **ยืนยันตัวตนด้วย JWT**: ล็อกอินสำเร็จจะได้ token กลับมาเก็บใน localStorage ของเบราว์เซอร์ ทุก request (ทั้ง REST API และ Socket.IO) ต้องแนบ token มาด้วยเสมอ — เซิร์ฟเวอร์ตรวจสอบจาก token ทุกครั้ง **ไม่เชื่อ userId ที่ client ส่งมาอีกต่อไป** (ของเดิมใครก็ส่ง userId ปลอมมาได้)
- token หมดอายุ 30 วัน หมดแล้วต้องล็อกอินใหม่ (เด้งกลับหน้า login อัตโนมัติ)
- ปุ่ม "ออกจากระบบ" อยู่ทั้งในหน้า "ทริปของฉัน" และแท็บ "สมาชิก"

### 🆕 ฐานข้อมูล PostgreSQL + ระบบหลายทริป (Multi-trip)
- **เชื่อมต่อ PostgreSQL จริง** ผ่าน `db/index.js` (ใช้ `pg` Pool + `DATABASE_URL`) เก็บ users / trips / members ลงฐานข้อมูลถาวร แทนการเก็บในหน่วยความจำแบบเดิมที่ข้อมูลหายทุกครั้งที่รีสตาร์ทเซิร์ฟเวอร์
- **หนึ่งบัญชีเข้าได้หลายทริปพร้อมกัน**: ล็อกอินครั้งเดียว เห็นทริปเดิมทั้งหมดจากทุกอุปกรณ์ที่ล็อกอินด้วยบัญชีเดียวกัน และสลับไปมาระหว่างทริปได้
- **สร้าง/เข้าร่วมทริปด้วยรหัส 6 หลัก**: รหัสทริป (trips.id) ใช้เป็นทั้ง ID และรหัสเชิญเพื่อนในตัวเดียว หน้า "ทริปของฉัน" ให้สร้างทริปใหม่ หรือกรอกรหัสเพื่อนเพื่อเข้าร่วม
- **เปิด/ปิดทริป (สวิตช์ใหญ่ระดับทริป)**: ทริปที่ "ปิด" แล้ว (คอลัมน์ `ended_at` มีค่า — เช่นทริปเก่าที่จบไปแล้ว) จะไม่รับ/ไม่กระจายตำแหน่ง GPS จากสมาชิกอีกต่อไป — เปิดกลับมาใช้งานใหม่ได้ทุกเมื่อ ปุ่มอยู่ที่แท็บ "สมาชิก"
- **เปิด/ปิดแชร์ตำแหน่งรายทริป (สวิตช์ที่ header)**: คอลัมน์ `gps_enabled` ในตาราง `members` แยกอิสระต่อทริป เช่น เปิดแชร์ในทริป A แต่ปิดในทริป B ได้ในเวลาเดียวกัน
- **แยกห้อง Socket.IO ตามทริป**: ตำแหน่งของแต่ละทริปจะไม่รั่วไปให้ทริปอื่นเห็น (และ Socket.IO เองก็ต้องยืนยัน token ก่อนเชื่อมต่อด้วย)

## REST API
| Endpoint | ต้องล็อกอิน? | คำอธิบาย |
|---|---|---|
| `POST /api/auth/register` | ❌ | สมัครสมาชิก `{ username, password }` |
| `POST /api/auth/login` | ❌ | เข้าสู่ระบบ คืน `{ token, user }` |
| `GET  /api/auth/me` | ✅ | ตรวจสอบ token ปัจจุบัน คืนข้อมูลบัญชี |
| `POST /api/whoami` | ✅ | รายการทริปทั้งหมดที่บัญชีนี้เข้าร่วม |
| `POST /api/trips` | ✅ | สร้างทริปใหม่ `{ tripName }` |
| `POST /api/trips/join` | ✅ | เข้าร่วมทริปด้วยรหัส `{ code }` |
| `GET  /api/trips/:tripId/members` | ✅ | รายชื่อสมาชิก + พิกัดล่าสุด |
| `PATCH /api/trips/:tripId/active` | ✅ | เปิด/ปิดทริป `{ isActive }` |
| `PATCH /api/trips/:tripId/share` | ✅ | เปิด/ปิดแชร์ตำแหน่งของฉันในทริปนี้ `{ enabled }` |

Endpoint ที่ต้องล็อกอินทั้งหมดต้องแนบ header `Authorization: Bearer <token>` มาด้วย

## ต่อยอดฟีเจอร์ที่เหลือ
แท็บ "กำหนดการ", "ค่าใช้จ่าย" ตอนนี้เป็นหน้า placeholder ที่วางโครง UI ไว้แล้ว
ตาราง `itinerary_items` ใน `db/schema.sql` เตรียมไว้ให้แล้ว พร้อมต่อยอด API/หน้าบ้านสำหรับกำหนดการเดินทางได้ในขั้นถัดไป (ค่าใช้จ่ายต้องเพิ่มตารางใหม่)

## ⚠️ ประวัติการแก้ไข
**รอบก่อนหน้า** — สาเหตุที่สร้างทริปไม่ได้: โปรเจกต์เดิมมีไฟล์ `db.js` (SQLite) วางอยู่นอกโฟลเดอร์ `db/` — เมื่อ `server.js` เรียก `require("./db")` Node.js จะเลือกไฟล์ `db.js` ก่อนเสมอ ทำให้ `db/index.js` (PostgreSQL) ที่ตั้งใจใช้จริงไม่ถูกเรียกใช้เลย แถม `better-sqlite3` ก็ไม่ได้ติดตั้งไว้ เซิร์ฟเวอร์เลย crash ตั้งแต่ต้น และไม่มีใครเรียก `dotenv.config()` ทำให้ `.env` ไม่ถูกโหลดด้วย — แก้โดยลบ `db.js` ที่ชนกันทิ้ง และเชื่อม `server.js` เข้ากับ `db/index.js` จริง

**รอบนี้** — เปลี่ยนจากการอิง "userId" ที่ client สร้างเองใน localStorage (ไม่มีการยืนยันตัวตนจริง ปลอมได้) มาเป็น **ระบบสมัครสมาชิก/เข้าสู่ระบบจริง** ด้วย username+password (bcrypt hash) และ JWT — เพิ่มตาราง `users`, เปลี่ยน `members.device_id` เป็น `members.user_id` อ้างอิง `users.id`, เพิ่มไฟล์ `auth.js`, และป้องกันทุก endpoint ที่เกี่ยวกับทริปด้วย middleware `requireAuth` (รวมถึง Socket.IO handshake ด้วย)
