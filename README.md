# TripMate — Live Location (Demo)

## วิธีรันโปรเจกต์

1. ติดตั้ง dependencies:
   ```
   npm install
   ```
2. ตั้งค่าฐานข้อมูล — คัดลอก `.env.example` (หรือแก้ `.env` ที่มีอยู่) แล้วใส่ connection string ของ PostgreSQL จริง:
   ```
   DATABASE_URL=postgres://user:password@localhost:5432/tripmate
   ```
   ต้องสร้างฐานข้อมูลชื่อ `tripmate` (หรือชื่อที่ตั้งใน URL) ไว้ล่วงหน้าด้วย `createdb tripmate` — ตารางข้างในจะถูกสร้างอัตโนมัติจาก `db/schema.sql` ตอนสตาร์ทเซิร์ฟเวอร์ครั้งแรก (ปลอดภัยที่จะรันซ้ำ)
3. รันเซิร์ฟเวอร์:
   ```
   node server.js
   ```
   ถ้าเชื่อมต่อสำเร็จจะเห็น `[db] Connected to PostgreSQL and schema is ready.` ถ้าไม่ตั้ง `DATABASE_URL` แอปจะยังเปิดหน้าเว็บได้ แต่ฟีเจอร์สร้าง/เข้าร่วมทริปจะใช้งานไม่ได้ (มี warning เตือนใน console)
4. เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`
   - เปิดหลายแท็บ/หลายเครื่อง (ในวง LAN เดียวกัน) เพื่อจำลองสมาชิกหลายคน
   - อนุญาตการเข้าถึงตำแหน่ง (Location) เมื่อเบราว์เซอร์ถาม

## สิ่งที่ปรับปรุงจากเดิม

- **หน้าตาใหม่**: ดีไซน์ทันสมัย มี header, แท็บเมนู, สถานะการเชื่อมต่อแบบเรียลไทม์
- **ระบุชื่อสมาชิก**: ใส่ชื่อก่อนเข้าร่วม แทนการเห็นแค่ socket id
- **แถบสมาชิก (Sidebar)**: เห็นรายชื่อ สี และเวลาที่อัปเดตตำแหน่งล่าสุดของแต่ละคน
- **Marker สีต่างกันต่อคน** + popup แสดงชื่อ
- **ปุ่ม "ไปยังตำแหน่งของฉัน"** (🎯) และปุ่มซูมแผนที่
- **โค้ดฝั่งเซิร์ฟเวอร์แข็งแรงขึ้น**: จัดการ join/disconnect สะอาดขึ้น ป้องกันชื่อว่าง/ยาวเกิน
- **Responsive**: ใช้งานได้บนมือถือ

### 🆕 ฐานข้อมูล PostgreSQL + ระบบหลายทริป (Multi-trip)
- **เชื่อมต่อ PostgreSQL จริง** ผ่าน `db/index.js` (ใช้ `pg` Pool + `DATABASE_URL`) เก็บ trips / members ลงฐานข้อมูลถาวร แทนการเก็บในหน่วยความจำแบบเดิมที่ข้อมูลหายทุกครั้งที่รีสตาร์ทเซิร์ฟเวอร์
- **หนึ่งคนเข้าได้หลายทริปพร้อมกัน**: มี "ตัวตน" (deviceId) ถาวรเก็บใน localStorage ของเบราว์เซอร์ ทำให้กลับมาเปิดแอปแล้วเห็นทริปเดิมทั้งหมด และสลับไปมาระหว่างทริปได้
- **สร้าง/เข้าร่วมทริปด้วยรหัส 6 หลัก**: รหัสทริป (trips.id) ใช้เป็นทั้ง ID และรหัสเชิญเพื่อนในตัวเดียว หน้า "ทริปของฉัน" ให้สร้างทริปใหม่ หรือกรอกรหัสเพื่อนเพื่อเข้าร่วม
- **เปิด/ปิดทริป (สวิตช์ใหญ่ระดับทริป)**: ทริปที่ "ปิด" แล้ว (คอลัมน์ `ended_at` มีค่า — เช่นทริปเก่าที่จบไปแล้ว) จะไม่รับ/ไม่กระจายตำแหน่ง GPS จากสมาชิกอีกต่อไป — เปิดกลับมาใช้งานใหม่ได้ทุกเมื่อ ปุ่มอยู่ที่แท็บ "สมาชิก"
- **เปิด/ปิดแชร์ตำแหน่งรายทริป (สวิตช์ที่ header)**: คอลัมน์ `gps_enabled` ในตาราง `members` แยกอิสระต่อทริป เช่น เปิดแชร์ในทริป A แต่ปิดในทริป B ได้ในเวลาเดียวกัน
- **แยกห้อง Socket.IO ตามทริป**: ตำแหน่งของแต่ละทริปจะไม่รั่วไปให้ทริปอื่นเห็น

## โครงสร้างไฟล์
```
tripmate/
├── server.js          # Express + Socket.IO server + REST API จัดการทริป
├── db/
│   ├── index.js        # เชื่อมต่อ PostgreSQL (pg Pool) + รัน schema.sql อัตโนมัติ
│   ├── schema.sql       # โครงตาราง trips / members / itinerary_items
│   └── store.js         # query helpers ที่ server.js เรียกใช้ (async, คุยกับ Postgres)
├── .env                 # DATABASE_URL ของคุณ (ต้องตั้งเองต่อเครื่อง)
├── package.json
├── public/
│   ├── index.html     # join modal + trip picker + app shell
│   ├── style.css      # ดีไซน์ทั้งหมด
│   └── app.js         # ฝั่งไคลเอนต์ (ตัวตนถาวร, จัดการทริป, แผนที่, geolocation, socket)
```

## REST API สำหรับจัดการทริป
| Endpoint | คำอธิบาย |
|---|---|
| `POST /api/whoami` | ลงทะเบียน/อัปเดตชื่อผู้ใช้ คืนรายการทริปทั้งหมดที่เข้าร่วม |
| `POST /api/trips` | สร้างทริปใหม่ (ได้รหัสเชิญ 6 หลัก) |
| `POST /api/trips/join` | เข้าร่วมทริปด้วยรหัส |
| `GET  /api/trips/:tripId/members` | รายชื่อสมาชิก + พิกัดล่าสุดของทริป |
| `PATCH /api/trips/:tripId/active` | เปิด/ปิดทริป (ปิด = หยุดรับ GPS ทั้งทริป) |
| `PATCH /api/trips/:tripId/share` | เปิด/ปิดการแชร์ตำแหน่งของตัวเองในทริปนั้น |

## ต่อยอดฟีเจอร์ที่เหลือ
แท็บ "กำหนดการ", "ค่าใช้จ่าย" ตอนนี้เป็นหน้า placeholder ที่วางโครง UI ไว้แล้ว
ตาราง `itinerary_items` ใน `db/schema.sql` เตรียมไว้ให้แล้ว พร้อมต่อยอด API/หน้าบ้านสำหรับกำหนดการเดินทางได้ในขั้นถัดไป (ค่าใช้จ่ายต้องเพิ่มตารางใหม่)

## ⚠️ สิ่งที่แก้ไขในรอบนี้ (สาเหตุที่สร้างทริปไม่ได้)
โปรเจกต์เดิมมีไฟล์ `db.js` (SQLite) วางอยู่นอกโฟลเดอร์ `db/` — เมื่อ `server.js` เรียก `require("./db")` Node.js จะเลือกไฟล์ `db.js` ก่อนเสมอ ทำให้ `db/index.js` (PostgreSQL) ที่ตั้งใจใช้จริงไม่ถูกเรียกใช้เลย แถม `better-sqlite3` ก็ไม่ได้ติดตั้งไว้ เซิร์ฟเวอร์เลย crash ตั้งแต่ต้น และไม่มีใครเรียก `dotenv.config()` ทำให้ `.env` ไม่ถูกโหลดด้วย
แก้แล้วโดย: ลบ `db.js` ที่ชนกันทิ้ง, เพิ่ม `db/store.js` เป็นชั้น query สำหรับ PostgreSQL ตาม `db/schema.sql` ที่มีอยู่แล้ว, เชื่อม `server.js` เข้ากับ `db/index.js` จริง, เพิ่ม `require("dotenv").config()`, และแก้ `package.json` ให้มี `pg`/`dotenv` แทน `better-sqlite3`/`uuid` ที่ไม่ได้ใช้
